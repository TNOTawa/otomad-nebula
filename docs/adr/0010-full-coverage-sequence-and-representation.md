# ADR 0010：全片覆盖序列与表征分层（v0.4）

- 状态：已接受（v0.4 开发中）
- 日期：2026-10-25
- 相关：ADR 0002（片段采样规则）、ADR 0001（向量版本）、`docs/plans/v0.4-full-coverage-design.md`

## 背景

v0.3 的作品表示是“在整条时间轴均匀选最多 5 段 8s 片段，分别编码后求平均”。
它有三个已确认的局限：最多只看 40s；作品向量丢失片段顺序与变化；聚合算法与
PE-AV 编码绑定在同一个版本号里，任何聚合器实验都要重新编码视频。

## 决策

### 1. 新增独立的 `plan_full_coverage()`，不修改 `plan_clips()`

旧 `plan_clips()` 的语义是“均匀选最多 N 段”，不是“连续覆盖”。直接把
`clips_per_work` 调大不能保证尾段与时间间隙。全片计划采用几何均匀步长：

- `n = ceil((duration - clip) / (clip - overlap)) + 1`，`step = (duration - clip)/(n-1)`；
- 第 i 个窗口起点 `i*step`，最后一个窗口精确锚定 `duration - clip`；
- 所有窗口长度 = clip（整片短于 clip 时退化为单窗口），因此无未覆盖间隙、
  无越界、无短尾填充；
- 每个窗口的权重 = 对 `1/覆盖计数(t)` 的积分并归一，保证 ∑weight=1 且
  时间轴上每一秒的总权重为 1，避免尾段重叠被重复加权。

这是确定性纯函数，可在任何机器复现。

### 2. 序列层与表征层分离

- **序列层**（`data/embeddings/<sequence_version>/`）：PE-AV 有序片段向量、
  片段窗口时间与权重、高频事件文件。编码一次，长期复用。
- **表征层**（`data/representations/<name>/<sequence_version>/`）：不同聚合器
  生成的作品向量（Full Mean / Temporal Stats / 未来 Transformer）。聚合器变化
  只新增表征，绝不重新下载/解码/编码 PE-AV。
- 版本号：`Config.embedding_version` 按 `sampling.mode` 返回激活的序列版本；
  `legacy_embedding_version` 保留旧公式，旧数据不迁移、不覆盖。

### 3. 片段级持久化与恢复

每个 batch 编码完成后原子写 `.partial/batch_{k}.npz` 并更新 `sequence_states`；
进程中断后只补编码缺失批次。只有全部批次完成才写最终 npy、登记 embedding、
标记 completed、清理临时文件。部分失败不污染正式向量。

### 4. 高频事件版本独立于序列版本

事件扫描（`events_v1`）的算法版本记录在事件文件、`event_manifest.json` 与
表征参数中。改进事件算法时可以只重扫事件/重建表征，而不改变 PE-AV 序列版本；
代价是若原始视频已删除，重扫需要重新下载（本地作品始终保留原文件）。

### 5. 地图绑定表征

`map_runs` 增加 `representation_id`，新地图只能由某一个表征构建；不同表征/
不同序列的向量禁止混入同一 UMAP 输入，地图坐标不跨表征比较。旧地图在 schema
v3 迁移时回填到对应 `legacy_5clip_mean` 表征。

### 6. 事件扫描不把“高同步”定义为更好

音画事件关系只记录时间相关、偏移、重合率等结构，不评分、不排序；刻意错位、
反差与延迟呼应同样是音MAD结构的一部分。

### 7. 336p 预处理作为新序列版本实验

`media.clip_height=336` 会改变向量，因此必须体现在序列版本号（`_h336`）中，
先在 10 部作品上与原生分辨率对比耗时与余弦差异，不自动转正。

## 后果

- 旧向量/旧片段/旧地图完全保留；app 可切换表征空间；
- 全片编码成本约为旧的 4–5 倍（片段数 ~23 vs 5），需后台批次运行；
- 事件文件增加约 0.5–1MB/部作品；
- v0.5 Transformer 只读取已保存的序列/事件特征，不做全片重编码；
- 需要新增测试覆盖覆盖完整性、恢复、反转顺序敏感性、版本隔离与地图隔离。
