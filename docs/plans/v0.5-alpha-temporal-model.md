# v0.5-alpha：分层音画时序模型设计（冻结编码器）

> 状态：设计已定稿，按 v0.5-alpha 实现；训练只用于验证“可学习时序表征是否成立”，
> 不宣布任何风格/流派结论，不覆盖 v0.4.x 表征与地图。
> 前置：v0.4.3.1 窗口权重/三层版本已修复；v0.4.4 共识融合是观察性证据。

## 1. 目标与非目标

目标（按优先级）：
1. 在现有 110 部作品上跑通“局部音画对齐 → 全曲时序聚合”的端到端训练与验证。
2. 验证三件事：时间敏感性（打乱顺序/错位音画后指标变差）、跨模态预测（masked segment / AV 配对）、
   表征不坍缩且不比 Full Mean 更差（高维近邻稳定性）。
3. 保存可复现的 checkpoint、模型版本与验证 JSON，供下一步决定是否扩大训练。

非目标：
- 不做风格分类、不做人工流派标签；不用“Transformer 星云更整齐”证明训练成功。
- 不重新训练/微调 PE-AV、CLIP、DINOv2（全部冻结，只读已保存向量）。
- 不覆盖 Legacy / Full Mean / Temporal Stats / Dense Visual 旧表征或地图。
- 不在本轮把研究模型注册成正式主表征/默认地图。

## 2. 输入层（全部来自已有落盘数据）

| 输入 | 来源 | 时间分辨率 | 用途 |
| --- | --- | --- | --- |
| PE-AV joint/audio/video | `data/embeddings/<sequence_version>/<work_id>/clip_{joint,audio,video}.npy` (W,1024) | 8s 窗口 | 局部段上下文 / 重建目标 |
| CLIP 帧向量 | `data/visual_dense/<clip_frame_version>/<work_id>/dense_visual.npz` `per_frame` (N,512) | 8fps | 局部视觉 token |
| DINOv2 帧向量 | 同上 `<dino_frame_version>` (N,384) | 8fps | 局部视觉 token |
| 音频事件 | `event_scan.npz` `audio`/ `av` (100Hz, 各 6 维) | 10ms | 局部音频 token 统计 |
| 视频事件 | `event_scan.npz` `video` (30fps, 6 维) | 33ms | 局部视觉事件 token 统计 |
| 窗口时间/权重 | `clip_times.npy` (W,4 = start,duration,length,weight) | — | 段边界、mask、目标 |

**窗口计划 = 8s/0 重叠（PE-AV 窗口）**；局部 token 采用固定 0.5s 分箱（8s 段内 16 个 bin）。
每个 bin 内：
- 视觉：落在该 bin 的帧向量做 L2 后均值；无帧则零向量 + mask=False。
- 音频事件：落在该 bin 的 100Hz audio 6 维 + av 6 维做 mean/std → 24 维。
- 视觉事件：落在该 bin 的 30fps video 6 维做 mean/std → 12 维。

视觉/音频 token 数量固定为每段 16（短段缺 bin 用 mask 掉）；段数 W 变长，最大 128（超长作品按前 128 段截断并记录）。

数据产物：`data/v05_tokens/<dataset_version>/<work_id>.npz`（fp16，含 arrays 与 mask）+ `manifest.json`；
数据集版本 `v05_alpha_v1`，记录 frame/sequence/event 版本、bin_seconds、特征维、创建时间。
生成命令：`python tools/build_v05_tokens.py --version v05_alpha_v1 --force`。

## 3. 模型（small，全冻结输入）

```
local segment (<=8s)
  PE-AV joint/audio/video (1024 each) ──project──> 3 个 segment context token
  visual bins (16, 512/384) ──project──> visual tokens
  audio bins  (16, 24)      ──project──> audio tokens
  video-event bins (16, 12) ──project──> visual-event tokens
  [CLS] + visual/audio/event tokens + 模态嵌入 + 段内位置编码
        └─ 2 层 TransformerEncoder（4 heads, hidden 256）─┘
        └─ CLS + masked mean → segment token (256)
temporal: W segment tokens + segment positional encoding + valid mask
        └─ 2 层 TransformerEncoder（4 heads, hidden 256）─┘
        └─ masked mean / CLS → work vector (256)
heads:
  masked segment prediction: 256 -> 1024（预测被 mask 段的 PE-AV joint）
  AV mismatch: [visual-pool; audio-pool] -> 2 类
  order recovery: 3 个连续 segment 的 token -> 3! = 6 类
```

默认超参：hidden=256、heads=4、local_layers=2、temporal_layers=2、dropout=0.1、max_segments=128、order_k=3。
Padded 段/缺失 token 必须通过 mask 完全屏蔽（测试断言：改 padding 内容不影响输出）。

## 4. 训练目标（自监督，无人工标签）

1. **Masked segment prediction（主）**：随机 mask 20% 段（至少 1 段），模型用上下文预测该段冻结的
   PE-AV joint 向量（L2 归一化后 MSE + 1-cosine），只在有效段上计损失。
2. **AV time-mismatch（辅）**：每段取真实视觉/音频与“错位音频”（同一作品随机平移 ≥1 段，或 batch 内
   其它作品）组成负例，二分类；正负各 50%。
3. **Local segment order（辅）**：随机取 3 个连续有效段，打乱后预测排列（6 类），使用其 temporal 输出 token。

损失 = w_mask * mask_loss + w_av * av_loss + w_order * order_loss（默认 1.0 / 0.5 / 0.5）。
优化器 AdamW lr=1e-3、weight_decay=0.01、batch=4 部、epochs=30（早停按 val mask cosine）。

## 5. 数据集划分与验证

- 划分：按 work_id 的确定性 hash 取 90/20（train/val），固定 seed=42；报告写清 work_id 列表文件。
- 指标：
  - mask prediction：val cosine / MSE，与“用 Full Mean 均值向量代替预测”的基线比较；
  - AV mismatch：val accuracy / AUC，chance=0.5；
  - order：val accuracy，chance=1/6；
  - 时间敏感性：把 val 作品段顺序反转/随机打乱，mask cosine 必须下降；AV 错位负例准确率必须高于随机；
  - 表征质量：work vector 的 pairwise cosine 分布（不坍缩）、有效秩、与 Full Mean 的 Top-5 Jaccard/邻域稳定性；
  - 泄漏检查：用 work vector 线性/最近邻预测 duration（R²）与 author（balanced accuracy），记录但不以删除作品为代价。
- 通过标准（alpha 可行性，不是最终模型）：
  - mask cosine > 0.5 且显著优于常量均值基线；
  - order accuracy > 1/6（如 ≥0.30）；AV accuracy > 0.6；
  - 顺序打乱后 mask cosine 下降 ≥5%；
  - work vector 有效秩 > 8，Top-5 近邻与 Full Mean Jaccard 在 0.3–0.8（既不复制也不完全无关）。

## 7. 风险与下一步

- 100Hz 音频事件是声学统计（能量/通量等），不是语义音频嵌入；若 AV 配对仅学到节奏峰值，
  下一步优先补**密集音频语义特征**，而不是继续升级视觉编码器。
- 110 部作品、帧级高度相关，不能把帧数当独立样本；alpha 只验证可行性。
- 局部 token 0.5s 是折中；快速闪帧仍需 30fps 子集或事件轨迹补充。
- 不宣称“逐帧语义理解”或“学到可靠流派”；v0.5-beta 再决定是否扩大数据/模型与正式注册。
